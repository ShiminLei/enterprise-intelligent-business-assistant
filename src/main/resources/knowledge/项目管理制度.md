# 项目管理制度

本制度规定公司项目中任务的状态管理、优先级、指派规则以及里程碑和周报要求，所有项目成员均须遵守。

## 一、任务状态定义

任务共有以下 4 种状态：

| 状态 | 含义 |
| --- | --- |
| 待开始 | 任务已创建并指派负责人，尚未开始执行 |
| 进行中 | 任务负责人已开始执行 |
| 已完成 | 任务已按要求完成并通过验收 |
| 已取消 | 任务因需求变更等原因不再执行 |

「待开始」和「进行中」的任务统称为未完成任务。新建任务的状态一律为「待开始」。

## 二、任务状态流转规则

任务状态只允许按以下方式变更：

- 待开始 → 进行中：任务负责人开始执行任务。
- 进行中 → 已完成：任务完成并通过验收。
- 进行中 → 待开始：任务暂停，需要重新排期（退回）。
- 待开始 → 已取消：任务不再需要执行。
- 进行中 → 已取消：任务执行中因需求变更等原因终止。

「已完成」和「已取消」为终态，不能再变更为其他状态。任务不能从「待开始」直接变为「已完成」，必须先变为「进行中」。

## 三、任务优先级

| 优先级 | 含义 |
| --- | --- |
| 高 | 影响里程碑或关键交付，须优先安排资源 |
| 中 | 常规任务，按计划推进 |
| 低 | 可在资源允许时安排，延后对整体影响较小 |

高优先级任务延期时的风险判定标准更严格，详见《项目风险管理规定》。

## 四、任务指派与变更权限

- 只有项目负责人（项目经理）可以在其负责的项目中创建任务并指派负责人。
- 项目经理可以修改其负责项目中任意任务的状态。
- 团队成员只能修改分配给自己的任务的状态，不能创建任务，也不能修改他人任务的状态。
- 创建任务时必须明确任务名称、负责人、计划截止日期和优先级，计划截止日期不得早于创建当天。

## 五、里程碑管理

- 每个项目在立项时须设定里程碑，每个里程碑明确交付内容和计划日期。
- 里程碑到期前一周，项目经理须检查相关任务的完成情况；存在高风险延期任务时，按《项目风险管理规定》处理。
- 里程碑日期调整须经部门负责人同意。

## 六、项目周报

项目经理每周五前提交项目周报，内容包括：

1. 本周完成的任务和下周计划。
2. 当前延期任务清单及风险等级。
3. 需要协调的资源或问题。
