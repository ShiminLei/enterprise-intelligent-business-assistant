# 项目风险管理规定

本规定适用于公司全部研发与交付项目，用于统一项目延期风险的识别、分级、应对与上报。项目经理对所负责项目的风险管理负首要责任。

## 一、适用范围与职责

本规定适用于公司所有处于「计划中」或「进行中」状态的项目。

- 项目经理：负责每周识别项目风险，按本规定评定风险等级、制定应对措施并按时上报。
- 任务负责人：发现任务可能延期时，须在当天告知项目经理，并说明原因和预计完成时间。
- 项目管理办公室（PMO）：负责汇总各项目风险，跟踪高风险事项的处理进度。

## 二、延期风险等级

任务延期是指任务状态为「待开始」或「进行中」，且当前日期已超过计划截止日期。已完成或已取消的任务不计为延期。延期天数为当前日期与计划截止日期相差的自然日天数。

延期任务按以下标准评定风险等级：

| 风险等级 | 判定标准 |
| --- | --- |
| 低风险 | 延期 1–3 天 |
| 中风险 | 延期 4–7 天 |
| 高风险 | 延期超过 7 天；或高优先级任务延期超过 3 天 |

同时满足多个条件时，按最高的风险等级认定。例如，高优先级任务延期 5 天，按高风险处理。

## 三、各等级的应对措施

### 3.1 低风险

- 任务负责人在 1 个工作日内更新任务的预计完成时间。
- 项目经理在下一次项目周会上跟进，无需单独上报。

### 3.2 中风险

- 项目经理在 2 个工作日内与任务负责人确认延期原因，制定追赶计划（如调整资源、拆分任务、调整优先级）。
- 追赶计划须明确新的完成日期，并记录在项目周报中。

### 3.3 高风险

- 项目经理须在 1 个工作日内组织专题会议，分析根本原因，制定应对方案。
- 评估对项目里程碑和最终交付日期的影响；如影响里程碑，须同步调整项目计划并告知相关方。
- 必要时申请增派人员或调整项目范围。
- 按第四章要求上报。

## 四、风险上报流程

| 风险等级 | 上报对象 | 上报时限 |
| --- | --- | --- |
| 低风险 | 无需单独上报，在项目周报中体现 | 每周 |
| 中风险 | 部门负责人 | 2 个工作日内 |
| 高风险 | 部门负责人及项目管理办公室（PMO） | 1 个工作日内 |

同一项目同时存在 3 个及以上中风险任务时，视同一项高风险，按高风险流程上报。

## 五、风险分析报告要求

项目经理提交的风险分析报告至少应包含以下内容：

1. 延期任务清单：任务编号、任务名称、负责人、计划截止日期、已延期天数、优先级。
2. 每项延期任务的风险等级及判定依据（引用本规定第二章的具体条款）。
3. 应对措施：针对每项中、高风险任务的具体措施、责任人与完成时间。
4. 整体风险结论：对项目按期交付的影响评估，以及是否需要上报。

项目当前没有延期任务时，报告应明确说明，并给出整体风险结论。
