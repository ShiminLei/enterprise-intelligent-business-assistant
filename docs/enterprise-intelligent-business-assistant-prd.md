# 企业智能业务助手 PRD

| 项目 | 内容 |
| --- | --- |
| 文档状态 | 草稿 v0.4 |
| 需求来源 | 企业级 Java + AI 项目实战营作业（三）· 题目二：综合难度——企业智能业务助手 |
| 业务场景 | 项目管理助手 |
| 大模型 | 阿里云百炼：qwen-plus（对话）、text-embedding-v4（向量化，1024 维） |
| 更新日期 | 2026-09-26 |

## 1. 背景

项目经理和团队成员日常需要在多个地方来回查找信息：项目进度在项目管理系统里，任务状态在任务列表里，
公司的风险管理规定、项目管理制度在内部文档里。回答「项目 A 现在有什么风险？」这类问题，
往往需要人工查询多份数据、对照制度，再手工整理成报告。

本项目使用 Java + AI 构建一个企业智能业务助手。它不只回答问题，还能根据用户需求
**查询知识库、调用业务工具、访问业务数据并完成任务**。

## 2. 目标

1. 用户用自然语言提出业务需求，助手通过多轮对话理解并完成。
2. 助手能自动检索企业知识库（制度、规范），回答时引用来源。
3. 助手能通过 Java 业务工具（Tool Calling）查询和操作业务数据库。
4. 对于复杂问题，助手能自主规划并连续调用多个工具，综合后输出结果。
5. 系统可在本地一键启动运行，并能演示一个完整的 AI 业务处理过程。

**评价重点（来自作业要求）**：系统能否实际运行、Java 与 AI 能力是否真正结合、能否解决设定的业务问题。

## 3. 用户角色

| 角色 | 说明 | 典型诉求 |
| --- | --- | --- |
| 项目经理 | 负责一个或多个项目的进度和风险 | 查看项目状态、找出延期任务、生成风险分析、指派任务 |
| 团队成员 | 执行具体任务 | 查询自己的任务、更新任务状态、查询公司制度 |

## 4. 范围

### 4.1 本期范围（In Scope）

- AI 对话（支持多轮）
- 企业知识库：文档导入、切分、向量化、检索
- 至少 3 个 Java 业务工具供 AI 调用（本 PRD 规划 5 个）
- 业务数据库：项目、任务、成员
- Agent 任务处理：自动判断调用哪些工具，支持多工具连续调用
- 简单的 Web 对话页面或 REST API
- README、运行截图 / 演示视频、AI 编程说明

### 4.2 不在本期范围（Out of Scope）

- 完整的项目管理系统界面（甘特图、看板等）
- 与外部真实系统（Jira、飞书项目等）对接
- 生产级多租户、单点登录、细粒度权限体系
- 移动端

## 5. 功能需求

### FR-1 AI 对话

- FR-1.1 用户可通过自然语言提出业务需求。
- FR-1.2 支持基本的多轮对话：同一会话内，助手能记住上下文。
  例如用户先问「项目 A 有哪些延期任务？」，再问「其中优先级最高的是哪个？」，助手能正确理解「其中」。
- FR-1.3 支持新建会话、清空上下文。

**验收标准**：连续 3 轮以上有指代关系的对话，助手均能正确理解上下文。

### FR-2 企业知识库

- FR-2.1 至少建立一个业务知识库，内容为项目管理相关的企业资料，如：
  - 《项目风险管理规定》（风险等级定义、延期判定标准、应对措施、上报流程）
  - 《项目管理制度》（任务状态流转、里程碑要求）
  - 以上文档由项目自行编写，以 Markdown 格式随代码一起提交，作为示例知识库。
- FR-2.2 支持导入至少一种文档格式（PDF、Word、TXT、Markdown 之一），完成解析、文本切分和向量化存储。
- FR-2.3 AI 能根据用户问题自动检索相关资料，无需用户手动指定。
- FR-2.4 回答中展示引用的文档名称或相关原文片段。
- FR-2.5 知识库中检索不到相关内容时，助手明确告知「未找到相关规定」，不编造。

**验收标准**：提问「任务延期超过几天算高风险？」，回答与《项目风险管理规定》一致，并标注出处。

### FR-3 Tool Calling（业务工具）

至少开发 3 个 Java 业务工具供 AI 调用。本期规划如下：

| 工具 | 类型 | 说明 | 主要参数 |
| --- | --- | --- | --- |
| 查询项目 | 读 | 按名称或编号查询项目基本信息、负责人、计划起止时间、状态 | 项目名称 / 编号 |
| 查询任务 | 读 | 按项目、状态、负责人、是否延期等条件查询任务列表 | 项目编号、状态、负责人、是否延期 |
| 检索知识库 | 读 | 按问题检索知识库，返回相关片段和来源文档 | 查询文本、返回条数 |
| 创建任务 | 写 | 在指定项目下创建任务，并指定负责人、截止日期、优先级 | 项目编号、标题、负责人、截止日期、优先级 |
| 修改任务状态 | 写 | 更新任务状态（如 待开始 → 进行中 → 已完成） | 任务编号、目标状态 |

- FR-3.1 每个工具都有清晰的名称、用途描述和参数说明，供模型正确选择与调用。
- FR-3.2 工具通过 Java Service 访问业务数据库，不允许模型直接拼接 SQL。
- FR-3.3 写操作（创建任务、修改状态）执行前，助手需向用户展示将要执行的操作并获得确认。
- FR-3.4 工具调用失败或参数不合法时，返回明确的错误信息，助手据此向用户说明或追问。

**验收标准**：5 个工具均能被 AI 在对话中正确调用；写操作在用户确认前不会落库。

### FR-4 业务数据库

- FR-4.1 至少建立一个简单的业务数据库，包含以下核心实体：
  - **项目**：编号、名称、负责人、计划开始 / 结束日期、状态
  - **任务**：编号、所属项目、标题、负责人、优先级、状态、计划截止日期、实际完成日期
  - **成员**：编号、姓名、角色
- FR-4.2 提供初始化示例数据：至少 3 个项目、每个项目 10 条左右任务，其中包含若干延期任务，
  便于演示风险分析。
- FR-4.3 AI 通过 Java Service 或 Tool 查询和操作业务数据。

**延期任务定义**：未完成且当前日期已超过计划截止日期的任务（具体阈值以知识库中的规定为准）。

### FR-5 Agent 任务处理

- FR-5.1 AI 能根据用户问题判断需要调用哪些工具，以及调用顺序。
- FR-5.2 对于复杂问题，能连续调用多个工具，汇总各步结果后生成最终回答。
- FR-5.3 为防止无限循环，单次请求的工具调用次数设上限（如 10 次），超过则停止并说明原因。
- FR-5.4 界面或日志中可以看到本次处理调用了哪些工具、顺序和结果，便于演示和排查。

**核心演示用例**：

> 用户：「查询项目 A 目前有哪些延期任务，并结合公司的风险管理规定生成一份风险分析。」

期望处理链路：

1. **查询项目**：确认项目 A 存在，获取项目信息
2. **查询任务**：获取项目 A 下的延期任务
3. **检索知识库**：检索《项目风险管理规定》中关于延期与风险等级的条款
4. **AI 综合分析**：对照规定，逐项评估延期任务的风险等级
5. **输出结果**：生成风险分析报告，包括延期任务清单、风险等级、依据条款（附出处）、建议措施

后续追问示例：「帮我给张三创建一个任务，跟进其中风险最高的那项，周五前完成。」
→ 助手展示待创建的任务内容 → 用户确认 → 调用创建任务工具 → 返回结果。

### FR-6 基本交互

- FR-6.1 提供简单的 Web 对话页面（必需）：输入框、消息列表、引用来源展示、工具调用过程展示。
- FR-6.2 Web 页面通过后端 REST API（对话、知识库导入）工作，API 也可直接用于测试。

## 6. 非功能需求

| 编号 | 需求 |
| --- | --- |
| NFR-1 可运行 | 按 README 步骤可在本地启动运行；依赖尽量少，提供一键启动方式（如 Docker Compose） |
| NFR-2 密钥安全 | 代码仓库中不得出现真实 API Key；只需一个阿里云百炼 API Key，通过环境变量注入，提供配置示例，并在 README 中说明申请方式 |
| NFR-3 模型接入 | 对话与向量化统一使用阿里云百炼，经 OpenAI 兼容接口调用：对话模型 qwen-plus（需支持 Tool Calling），向量模型 text-embedding-v4（固定 1024 维）。模型名称可配置，均通过统一抽象层接入，更换模型或提供商时无需修改业务代码。更换 Embedding 模型或维度时需重建整个知识库索引 |
| NFR-4 可追溯 | 记录每次对话的工具调用和检索来源，便于演示与排查 |
| NFR-5 响应 | 普通问答在可接受时间内返回；多工具任务在界面上展示处理进度 |

## 9. 与项目宪法的关系

本 PRD 需遵守 [项目宪法](../.specify/memory/constitution.md)，重点对应：

- 原则 I（安全与数据隐私）：不提交密钥；写操作需确认；知识库内容视为不可信输入。
- 原则 II（有据可依、可追溯的 AI）：回答引用来源，检索不到不编造；记录工具调用链路。
- 原则 V（简单性）：采用单 Agent + 工具调用，不引入多智能体编排。

宪法已于 v2.0.0 按本作业规模精简（删除多租户隔离、CI 评估门禁、依赖漏洞扫描、分布式追踪等要求），
与本 PRD 不再冲突；各原则的具体落实见 `specs/001-project-management-assistant/plan.md` 的 Constitution Check。
